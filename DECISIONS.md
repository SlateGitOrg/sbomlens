# Decisions

Each ruling records the choice, why it was made, and the cost if it is wrong.

- Ruling: Rust library + thin `sbomlens` binary, with CLI logic in `src/cli.rs` inside the library — commands can be tested in-process and counted by coverage — cost if wrong: small; the binary could be split out later.
- Ruling: Parse only the JSON forms: CycloneDX 1.5/1.6 and SPDX 2.3. CycloneDX 1.2–1.4 and SPDX 2.2 are accepted with a warning; everything else is rejected — this is what the brief scopes, and older JSON versions are structurally compatible for the fields used — cost if wrong: XML/tag-value users must convert first.
- Ruling: Merge components that share a purl (minus subpath) inside one SBOM, and alias the second reference — syft-style SBOMs list one package once per location, and duplicates would double-count findings — cost if wrong: two genuinely different artifacts with identical purls collapse into one.
- Ruling: CycloneDX nested `components[]` get a containment edge from their parent — without it, nested components in documents that omit `dependencies` are unreachable from the root and have no "introduced via" path — cost if wrong: containment and dependency are not distinguished in paths.
- Ruling: Several CycloneDX `licenses[]` entries are combined with `AND` — conservative, since all stated licenses apply; the spec does not define the semantics — cost if wrong: spurious "license changed" diffs when a producer meant `OR`.
- Ruling: SPDX license = `licenseConcluded`, falling back to `licenseDeclared` when concluded is `NOASSERTION`/`NONE` — the concluded value is the analyst's determination — cost if wrong: declared and concluded values can differ, and only one is shown.
- Ruling: npm purl names are not lower-cased — the purl-spec test suite does not require it, and legacy mixed-case npm packages exist — cost if wrong: a lookup miss for SBOMs that spell a name with different case than OSV.
- Ruling: The two purl-spec cases "subpath cannot contain '.'/'..'" are checked only by canonical form — the suite records the un-normalized subpath in their field values, while we normalize at parse time — cost if wrong: none for matching; the subpath does not affect identity.
- Ruling: npm versions are strict SemVer after `v`/`=` trimming; loose node-semver coercion (`1.2` → `1.2.0`) is not applied — lockfile versions are always full SemVer, and coercion would hide malformed data — cost if wrong: hand-edited SBOMs with short versions are reported as version errors.
- Ruling: Maven ordering follows Apache Maven 3.9.9 `ComparableVersion` (MNG-6964 and MNG-7644 included), checked against its own test vectors — OSV's Maven ecosystem is defined by Maven's ordering — cost if wrong: Gradle-specific ordering differences in rare edge cases.
- Ruling: The POM-reference example `"1-ga-1" = "1-1"` is not asserted — Maven 3.9.9's implementation orders them differently; we match the implementation, not the prose — cost if wrong: none observed in the OSV data.
- Ruling: Same-version OSV events are ordered as interval endpoints (`fixed < introduced < last_affected`), not by document order — found by the interval-model property test; document order made `[last_affected X, introduced X]` affect X+1 — cost if wrong: an OSV producer relying on document order for ties would be read differently (none observed).
- Ruling: `GIT` ranges, unknown ecosystems and purl-less components are counted as not evaluable and are never matched with a fallback ordering — a confident wrong answer is worse than a reported gap — cost if wrong: lower recall on mixed OS-package SBOMs; it is visible in report counters.
- Ruling: A component whose version fails to parse under some advisory's scheme is still checked against the other advisories, and is listed under "not fully checked" — partial coverage beats silent skipping — cost if wrong: none; the listing keeps it visible.
- Ruling: Severity comes from a CVSS v3 base score computed from the vector, then GitHub's qualitative label, then `unknown`; CVSS v4 is not scored — v4 needs the MacroVector lookup table, which is out of scope for v1 — cost if wrong: some findings sort as `unknown` and do not trip `--fail-on`.
- Ruling: `--fail-on` counts only active findings (after VEX) and treats `unknown` as below `low` — VEX is the mechanism for accepted risk — cost if wrong: an unscored critical issue would not fail the build. This is documented in the README.
- Ruling: VEX `not_affected`/`fixed` findings stay in all outputs, as SARIF suppressions and in a "suppressed" table — this keeps the audit trail — cost if wrong: noisier reports.
- Ruling: Invalid VEX statements are ignored with a warning, not treated as errors — one bad statement should not block a scan; ignoring it cannot hide a finding — cost if wrong: users may miss the warning.
- Ruling: VEX statements that matched a finding but lost on timestamp count as used — "unused" means "matched nothing", which is the stale-triage signal — cost if wrong: superseded statements are not flagged for cleanup.
- Ruling: The finding count after alias merging is computed per component, with union-find over id+aliases — GHSA/PYSEC/GO duplicates are one vulnerability, but the same CVE in two packages is two — cost if wrong: transitive alias chains merge advisories that some would keep separate.
- Ruling: Diff pairs leftover versions in ascending order within each identity — this handles npm's multiple-version trees without heuristics — cost if wrong: when one side has more versions, the leftover reported as added/removed may not be the one a human would pick.
- Ruling: Real SBOMs come from first-party generators already on the machine (`npm sbom`, `uv export`), not from syft — running a downloaded third-party binary was not permitted in this environment, and first-party generators need no extra trust — cost if wrong: no syft-shaped SBOM in the fixtures; the cargo, Go and Maven coverage comes from a hand-written CycloneDX 1.6 fixture.
- Ruling: The OSV subset holds every advisory for every package in the fixtures, not only the matching ones — negatives (non-affected versions, other ranges) are needed for a meaningful agreement eval — cost if wrong: 2.4 MB of fixtures instead of about 0.5 MB.
- Ruling: Ground truth for the agreement eval is OSV.dev's own matcher, recorded at fetch time — it is the reference implementation of the schema — cost if wrong: OSV.dev's own bugs would be reproduced, not detected.
- Ruling: The benchmark is a dependency-free `harness = false` bench with medians over `Instant` timings, not criterion — it keeps compile time and dependencies down on a shared build machine — cost if wrong: weaker statistics; disclosed in the README.
- Ruling: MSRV is 1.85 for the library and binary (CI builds it); the proptest dev-dependency needs 1.88, so tests run on stable — cost if wrong: contributors on 1.85 cannot run the test suite.
- Ruling: Clippy runs in pedantic mode with `-D warnings`; `doc_markdown` and `many_single_char_names` are allowed crate-wide; examples/bench allow `cast_precision_loss`, and the property-test generators allow three style lints — these lints fire on product names and math-style code without improving it — cost if wrong: none functional.
